02 Approach

The work comes first. Then the software.

Most problems aren't software problems. They're payments tracked in spreadsheets, follow-ups that depend on memory, and managers calling for updates. I fix the work, then build what runs it.

i.

Follow the work

Sit with the team, trace how a loan, an enquiry or a site update actually moves today, and where it gets stuck.

ii.

Agree what changes

Decide what the system should do automatically, what stays human, and how everyone will know it's working.

iii.

Build in stages

Ship module by module with AI-assisted development, so the business keeps running while the system takes shape.

iv.

Make it stick

Roles, permissions, an audit trail and a clear view for management: a system people use, not one they work around.
